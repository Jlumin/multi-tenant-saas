# Phase 3 CRM／E-Commerce security

- All CRM and E-Commerce routes require authenticated tenant membership; there are no anonymous listing, customer, cart, or checkout APIs. Tenant scope is checked for every read/write. CRM PII and order reads are limited to `admin`/`manager`; product listings are readable by tenant members. Writes are Owner (`admin`) only for E-Commerce; CRM writes allow `admin`/`manager`. Viewers cannot access CRM PII or order records.
- Session mutations use CSRF-protected same-origin requests. Tenant IDs, actor IDs, product details and listing prices are never trusted from arbitrary client fields; strict serializers reject unknown keys.
- CRM customer code and tenant are immutable; customer deletion is prohibited. Consent and withdrawal are append-only, immutable in application code and PostgreSQL trigger. Audit records contain action and target UUID, not email/phone or consent payload.
- E-Commerce orders preserve price/member snapshots and idempotency key. Database triggers require lines and sandbox payment to agree with final order state. A sandbox payment capture cannot be replayed into a second stock issue; a paid order cannot be canceled in this phase.
- WMS reserves stock per selected warehouse and location while holding tenant row lock. Sellable quantity subtracts active reservation allocations. Ordinary WMS issue posting checks available quantity after active reservations; reservation capture consumes through WMS service, writes a normal issue document and append-only movement. Insufficient quantity rejects the whole transaction.
- Payment details are not collected or stored. Provider is constrained to `sandbox`; there are no external callbacks or secrets. Real payment, refund, email, restock notices and public checkout require separate threat review and design.
- Order records copy customer name/Email for the sales snapshot. Retention, export and deletion policy for this PII remains to be decided before production use.
