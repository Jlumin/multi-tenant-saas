## Issue 格式
每張 Issue 包含：問題與目標、範圍、排除範圍、依賴、實作注意事項、可勾選驗收條件、驗證方式、文件更新與交付物。
識別碼使用 BOOTSTRAP-001、TENANCY-001 等前綴；GitHub Issue number 是另一個識別碼。
流程：Backlog → Ready（範圍與依賴明確）→ In progress → Review → Done。
沒有建立對應 GitHub labels 或 project board；上述是流程定義。

## 第一次派工
1. 人工審查文件提案；文件尚未合併時，Codex 必須從文件分支建立實作分支，才能讀到規範。
2. 將 BOOTSTRAP-001 Issue 連結與來源分支交給 Codex，要求只做該 Issue。
3. 執行者檢查最新狀態後實作；遇到未決定事項，採文件中的預設提案並記錄，重大產品取捨再向使用者確認。
4. 提出 Draft PR，標明依賴文件分支；文件先合併後再調整目標分支。不得自行合併。

## PM 審查
逐項檢查驗收證據、租戶隔離、安全邊界、可重現啟動方式與範圍。
缺少證據退回修正；已知限制寫入 PR 與後續 Issue，不以完成宣告取代測試。

## 待使用者決定
產品服務對象與核心業務、登入供應商、正式部署環境、計費需求、租戶建立與邀請規則。
這些不阻擋本機骨架工作，但會阻擋對應正式產品功能。
