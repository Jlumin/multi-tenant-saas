## 產品目的與角色提案

### 產品目的（提案）

讓租戶管理商品目錄與銷售流程，讓買家瀏覽、選購及查看訂單。是否需要多商店、B2B 報價、促銷、會員分級與跨境銷售，需依目標客群確認後再納入。

### 角色候選

| 角色 | 可能操作 | 狀態 |
| --- | --- | --- |
| 店家 Owner | 管理商店設定、商品、價格、訂單及店員權限 | 提案；權限範圍待確認 |
| 店家操作人員 | 維護目錄、處理訂單、出貨／退款 | 提案；是否沿用 Owner/Member 或新增角色待確認 |
| 買家 | 公開瀏覽、購物車、下單、查看訂單、取消／退貨 | 提案；訪客與登入要求待確認 |
| 平台維運者 | 維護 SaaS 平台 | 沿用 TENANCY 邊界，不因此取得跨租戶訂單瀏覽權限 |

租戶 membership 的 Owner/Member 不等同買家 Customer。不得用信箱相同推論兩個身份必定屬於同一人，也不能因管理店面就授予平台級資料權限。

## 主要流程候選

以下流程用於找出需求，不等於已決定實作狀態或政策。

1. **開店與設定**：店家選擇租戶、設定店名、公開狀態、銷售區域、幣別、配送／取貨政策與訂單通知方式。
2. **目錄維護**：店家建立商品、SKU/變體、價格、描述、圖片、可見狀態；若商品對應 WMS SKU，透過 WMS 公開契約建立關聯，不能直接修改 WMS 主檔或庫存表。
3. **瀏覽與加購**：買家在公開 storefront 瀏覽商品，選擇規格與整數數量；伺服器重新確認商品仍可售、價格、商店狀態與目前購買限制。
4. **結帳與下單**：收集必要聯絡／配送資料，鎖定一份伺服器計算的價格及商品快照；確認運費、稅與付款方式後建立訂單。不能信任瀏覽器回傳的金額。
5. **付款與庫存**：支付供應商回呼須驗證來源、冪等及訂單參照；若有 WMS 整合，訂單與庫存需求透過契約處理，不能直接更新 WMS。超時、重送、付款失敗與庫存不足需定義一致狀態轉移。
6. **履約與售後**：店員準備／出貨／完成訂單；取消、退貨與退款各自保留可追溯紀錄，不刪除已確認交易。
7. **訂單查詢**：買家依已驗證帳號或高熵、限時且可撤銷的查詢憑證查看自己的訂單；商家僅能查看所屬租戶的訂單。

## 候選狀態與不變條件

### 訂單狀態候選

`草稿／待付款 → 已付款／待處理 → 處理中 → 已出貨／可取貨 → 已完成`，另外可能有 `付款失敗`、`逾時`、`取消`、`部分退款`、`已退款`。不同付款方法、貨到付款、自取及部分出貨可能需要不同轉移；須先決定需求再定稿狀態機。

### 安全與交易不變條件候選

- 私有讀寫依登入 session、有效 tenant membership 與角色；公開 storefront 也要由 server 解析有效商店，不能接受任意 tenantId 來瀏覽租戶管理 API。
- 商品／價格顯示可以快取，但結帳時由 server 重新驗證商店、商品、價格、可售狀態、配送選擇及總金額。
- 訂單建立時保存商品名稱、SKU、單價、數量、幣別、稅與折扣等交易快照；日後改商品資料不得改寫既有訂單。
- 每次結帳提交、付款供應商回呼、退款與庫存契約操作都需可冪等；重送不得重複建立訂單、扣款、退款或庫存異動。
- 付款「已成功」以可信的供應商確認為依據，不以瀏覽器 redirect 作為證明；敏感卡片資料不經本系統保存。
- 若使用庫存預留，訂單與 WMS 的失敗／逾時補償及重試需明確，不得出現無期限扣住庫存或已付款卻無可履約庫存的未定狀態。
- 訂單、付款與履約狀態變更寫 metadata audit，避免將買家地址、付款憑證、token 或完整 webhook payload 寫入一般日誌。
- 退貨／退款保留原交易關聯與操作者；支付已完成後，禁止以刪除訂單方式「退回」狀態。
- 買家地址、電話等個資只為已確認流程收集；權限、保存期限、匯出與刪除政策須在正式試用前定義。

## 核心驗收案例候選

- 租戶 A 的店員嘗試取得租戶 B 的管理目錄、訂單、買家地址或付款參照：拒絕且不洩漏資源存在。
- 未登入者只能存取商家明確公開的商品資訊；草稿店面、草稿商品及已取消上架商品不可公開。
- 買家竄改商品價格、折扣、租戶 ID、運費或訂單 ID：server 忽略／拒絕客戶端金額並按有效店面重算；不能讀取他人訂單。
- 同一結帳請求重送、同一 webhook 重送或併發回呼：最多產生一次訂單狀態轉移與一次外部副作用。
- 下單時商品價格、名稱與單位規格被保存為訂單快照；修改商品後既有訂單不變。
- 庫存不足、支付失敗／逾時、付款成功但 webhook 重送、取消競態與退款失敗都留下可復原且可稽核狀態，不形成重複扣庫存或扣款。
- 跨模組服務中斷時採明確重試／補償，不直接操作其他模組資料表。

## 實作前需核定的問題

1. 第一批服務對象是哪一類店家與買家？優先 B2C、B2B，或先為單一店家代管商品？
2. 一個 tenant 預期只有一間店，還是需要多店／多品牌？店面公開網址與自訂網域是否為 MVP 必要？
3. 商品是否直接販售 WMS SKU？是否有顏色／尺寸等變體、不同包裝價格、套組、客製品或無庫存商品？
4. 目標銷售地區、幣別、稅額／發票及顯示價格規則是什麼？
5. 結帳是否接受訪客？買家需否建立登入帳號、加入 CRM 會員或同意促銷？
6. 需要哪些付款方法與支付供應商？未付款訂單多久失效？退款／部分退款由誰核准？
7. 支援宅配、超商、自取或貨到付款中的哪些方式？運費如何計算？第一版是否可先人工處理履約？
8. WMS 庫存何時預留與扣減，預留多久；取消／付款失敗／退貨時如何釋回？缺貨但已付款如何處理？
9. 商品、訂單、地址、付款參照及稽核資料保存多久？是否需要買家匯出／刪除流程？
10. 商家員工是否使用 Owner/Member，或需新增商品管理、接單、出貨與退款等角色？

未回答的問題會阻擋相應的正式交易實作；可先做不連接金流／庫存的文件與目錄展示原型，但需另行明確開 Issue。

## ECOM-001 實作切片（暫定）

對應 Issue #25。此切片交付一個租戶店面、商品目錄管理，以及只讀公開商品瀏覽；它不是完整交易網站。以下是為了讓此目錄切片可實作而採用的暫定值，待本切片完工後由產品負責人一次確認：

- 一個租戶一間店；公開 URL 使用全域唯一的小寫 slug，建立後固定。
- 店面使用有效的三碼 ISO 4217 幣別；商品價格以該店幣別表示、非負、最多兩位小數。建立商品後暫不允許更換幣別，避免舊價格被重新解讀。此版本不處理稅、折扣或運費。
- E-Commerce 自有商品目錄，不映射 WMS SKU、不查或同步 WMS 庫存；每個商品只有單一規格。
- 店面 Owner 可新增／編輯店面與商品、上架／下架；Member 可讀管理目錄；未登入者只看啟用店面中的上架商品。
- 不支援購物車、買家帳號、訂單、付款、配送、退貨、圖片上傳、搜尋、自訂網域或通知。

管理端為 `/ecommerce`；租戶內管理 API 為 `/api/ecommerce/{tenantId}/store` 與 `/api/ecommerce/{tenantId}/products`；公開頁與唯讀 API 分別為 `/shop/{slug}` 和 `/api/shop/{slug}`。授權仍以 session、有效 membership、角色與服務端 tenant scope 為準，tenantId 僅是選擇器。店面與商品以軟性狀態停用／下架，資料庫拒絕硬刪除並保留 metadata audit。

本 Issue 的實作狀態與產品確認清單見 `docs/verification/ECOM-001.md`；其餘交易、會員與跨模組問題仍按上方「實作前需核定」清單逐 Issue 決定。
