# 多租戶 SaaS PRD

版本：0.1，2026-10-26，提案待產品確認。

## 已知事實
儲存庫名稱為 multi-tenant-saas，說明為 Agent for saas system；僅有 README。
尚無垂直產業、Agent 行為、付費模式、既有使用者或服務等級需求。
以下以「可驗證租戶隔離的 SaaS 基礎」作為初始方向，不能視為已核定商業範圍。

## 問題與目標
建立可在本機重現的工程起點，再加入身分、租戶、成員角色與一個最小資源流程。
成功標準：開發者能啟動；同一使用者能依有效 membership 存取租戶；租戶 A 無法讀寫租戶 B 的資料。

## 初始角色提案
- Owner：管理租戶與成員；不得移除最後一位 owner。
- Member：使用所屬租戶的業務資源；不得管理成員。
- 非成員／未登入者：不得取得租戶資料。
平台管理員、支援跨租戶存取等能力不在 MVP，禁止默認超級權限。

## MVP 使用流程（分期交付）
1. 使用者完成登入（供應商待選），建立或加入租戶。
2. 選擇租戶，後端驗證身分、membership 與角色。
3. 在租戶內建立、列出、查看、修改、刪除範例 project。
4. 非成員與另一租戶成員嘗試相同操作，均被拒絕且不洩漏資料。

## 功能範圍
M0：骨架、健康檢查、本機 PostgreSQL、工具鏈與 CI。
M1：正式身分整合、租戶、membership、授權、資料庫隔離測試。
M2：project CRUD、基本 UI、稽核事件與端到端測試。
BOOTSTRAP-001 只交付 M0；登入與 CRUD 不應在第一張 Issue 擴張實作。

## 排除範圍
付款訂閱、第三方 Agent 執行、LLM 串接、自動化工作流、邀請郵件、SSO、自訂網域、正式部署、用量計費。

## 非功能需求
- 伺服器端授權與資料層隔離；錯誤回應不得包含秘密或堆疊。
- UTC 時間、可重現 migration、可重現安裝、明確環境變數範例。
- CI 執行 lint、型別、測試與 build；資料庫測試使用獨立測試資料。
- 效能、可用性、保存期限與法遵要求尚未定義，正式上線前需補足。

## MVP 驗收
- 全新環境能依文件安裝與啟動。
- 使用者無有效 membership 不能選取或存取租戶。
- 兩租戶的列表與單筆 CRUD 交叉存取全部被拒絕。
- Member 無法執行 Owner 操作，最後一位 Owner 受保護。
- secrets 不在版本控制中；授權與隔離有自動化測試。

## 開放問題
目標客群、核心業務資源是否為 project、是否需要 Agent、租戶自助建立與邀請政策、登入與部署供應商。
