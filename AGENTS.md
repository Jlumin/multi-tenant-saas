# SME Cloud contributor instructions

- Phase 1 foundations through Phase 4 HR, the Phase 5 Restaurant first version, and Phase 6 operational readiness are approved and implemented. Phase 7 tenant branding and tenant-scoped image management was approved by the user on 2026-10-30; details are in `docs/architecture/tenant-branding-phase7.md`.
- Monorepo: `apps/backend` (Django/DRF), `apps/frontend` (Angular/TypeScript). Existing root `app`, `tests`, `main.py` are legacy Mini WMS; do not migrate or modify them implicitly.
- Modular monolith: modules `wms`, `ecommerce`, `crm`, `hr`, `restaurant`. Restaurant owns both QR ordering and staff POS.
- Each module owns its future tables and writes. Cross-module use goes through public services/contracts; no direct writes to another module's tables. Shared code contains technical primitives only.
- PostgreSQL is the integration/production database. Never silently substitute SQLite.
- No credentials, customer data or `.env` files in Git. Fail closed on missing configuration. Anonymous APIs are limited to health, session bootstrap/login, scoped Restaurant QR endpoints, and the Phase 8 opt-in read-only storefront. Enforce CSRF on login and all session mutations.
- Tests: backend `python manage.py check`, `python manage.py makemigrations --check --dry-run`, `python manage.py test`; frontend `npm ci`, `npm run typecheck`, `npm run build`; Compose config and integration smoke test per README.
- Update docs when changing boundaries, security or commands. Report skipped checks and environmental limitations honestly.
- Current approved boundary: CRM member/consent, authenticated E-Commerce listing/order sandbox integrated with WMS, HR employee attendance/corrections, Restaurant QR ordering/POS, tenant branding settings and authenticated tenant-scoped logo/product image access. Anonymous Restaurant APIs are limited to scoped QR menu lookup, order submission and QR image retrieval, protected by unguessable revocable table tokens, CSRF on writes and anonymous rate limits. Phase 8 separately allows an explicitly enabled tenant's read-only public catalogue and published logo/product images; checkout and customer data remain private and out of scope.
- Phase 6 operational hardening was approved on 2026-10-30. Phase 7 branding and image management was completed and validated. Phase 8 customer storefront was explicitly approved on 2026-10-31; scope is an opt-in public, read-only E-Commerce catalogue and a browser-only cart. Public checkout, customer identity, shipping details, notification subscriptions and real payment are not approved/defined in this phase. Validate opt-in behavior, public data minimization, tenant isolation and throttling before stopping/reporting Phase 8. Do not deploy externally or modify production data without separate explicit instruction. Keep dev Compose and production overlay distinct; production requires a trusted TLS edge proxy, real secret values supplied outside Git, encrypted offsite backups of both database and media, and an operator-reviewed migration window.
