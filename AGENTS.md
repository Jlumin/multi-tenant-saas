# SME Cloud contributor instructions

- Phase 1 foundations through Phase 4 HR, the Phase 5 Restaurant first version, and Phase 6 operational readiness are approved and implemented. Phase 7 tenant branding and tenant-scoped image management was approved by the user on 2026-10-30; details are in `docs/architecture/tenant-branding-phase7.md`.
- Monorepo: `apps/backend` (Django/DRF), `apps/frontend` (Angular/TypeScript). Existing root `app`, `tests`, `main.py` are legacy Mini WMS; do not migrate or modify them implicitly.
- Modular monolith: modules `wms`, `ecommerce`, `crm`, `hr`, `restaurant`. Restaurant owns both QR ordering and staff POS.
- Each module owns its future tables and writes. Cross-module use goes through public services/contracts; no direct writes to another module's tables. Shared code contains technical primitives only.
- PostgreSQL is the integration/production database. Never silently substitute SQLite.
- No credentials, customer data or `.env` files in Git. Fail closed on missing configuration. Public APIs are limited to health and session bootstrap/login; enforce CSRF on login and all session mutations.
- Tests: backend `python manage.py check`, `python manage.py makemigrations --check --dry-run`, `python manage.py test`; frontend `npm ci`, `npm run typecheck`, `npm run build`; Compose config and integration smoke test per README.
- Update docs when changing boundaries, security or commands. Report skipped checks and environmental limitations honestly.
- Current approved boundary: CRM member/consent, authenticated E-Commerce listing/order sandbox integrated with WMS, HR employee attendance/corrections, Restaurant QR ordering/POS, tenant branding settings and authenticated tenant-scoped logo/product image access. The Restaurant public API exception is limited to scoped QR menu lookup, order submission and QR image retrieval, protected by unguessable revocable table tokens, CSRF on writes and anonymous rate limits. No branding or product-image API is public; only health/session bootstrap/login and the existing scoped Restaurant QR endpoints allow anonymous access.
- Phase 6 operational hardening was approved on 2026-10-30. Phase 7 branding and image management is approved; validate its PostgreSQL migrations, tenant/RBAC isolation, upload limits and media persistence, then stop and report. Do not deploy externally or modify production data without separate explicit instruction. Keep dev Compose and production overlay distinct; production requires a trusted TLS edge proxy, real secret values supplied outside Git, encrypted offsite backups of both database and media, and an operator-reviewed migration window.
